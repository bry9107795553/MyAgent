# 移交摘要模板

> Coach 向 Receiver 移交项目时使用的标准化格式。确保 Receiver 能快速理解项目现状并开始修改。

---

## 模板

```markdown
## 移交摘要：{项目名}

### 项目概况
- 项目名：{project_name}
- 当前状态：{已完成 / Phase N 进行中}
- 项目路径：data/projects/{project_name}/
- 项目类型：{Web应用 / API服务 / 桌面应用 / ...}
- 初始开发日期：{YYYY-MM-DD}
- 交付日期：{YYYY-MM-DD}

### 已完成模块
- {模块1}：{简要说明，含技术栈关键词}
- {模块2}：{简要说明}
- {模块3}：{简要说明}

### 关键架构决策
- 技术栈：{前端框架 + 后端 + 数据库 + 构建工具}
- 部署方式：{部署平台 / 部署方式}
- 重要约定：
  - {约定1：如命名规范、目录结构}
  - {约定2：如状态管理方案}
  - {约定3：如 API 设计规范}
- 关键文件：
  - .architecture.md：{路径}
  - 入口文件：{路径}
  - 配置文件：{路径}

### 已知技术债
- [!!] 紧急：{描述 + tech_debt.md 编号}
- [!] 高：{描述 + tech_debt.md 编号}
- [i] 中：{描述}
- [~] 低：{描述}

### 用户要改什么
{用户原始请求的简要描述 + 改动类型（UI / 逻辑 / 架构 / 新增功能）}

### 用户偏好
- 沟通风格：{自然语言 / 简洁 / 教学式 / ...}
- 技术偏好：{偏好框架 / 工具 / 风格}
- 特殊要求：{如有}
```

## 填写示例

```markdown
## 移交摘要：待办事项应用 (todo_app)

### 项目概况
- 项目名：todo_app
- 当前状态：已完成（Phase 3 部署上线）
- 项目路径：data/projects/todo_app/
- 项目类型：Web应用
- 初始开发日期：2026-07-25
- 交付日期：2026-08-01

### 已完成模块
- Header 组件：顶部导航栏，含用户头像和搜索入口
- NavBar 组件：左侧导航，含任务分类和项目切换
- Sidebar 组件：右侧信息面板，含任务统计和日历
- TaskCard 组件：任务卡片，支持5种状态（待办/进行中/已完成/暂停/取消）
- TaskList 组件：任务列表，支持拖拽排序和批量操作
- TaskDetail 组件：任务详情弹窗，含描述、附件、评论
- Settings 组件：个人设置页，含主题、通知、账户管理

### 关键架构决策
- 技术栈：React 18 + TypeScript + Vite + Zustand + CSS Modules
- 部署方式：Vercel 静态部署
- 重要约定：
  - 组件命名：PascalCase，文件名与组件名一致
  - 状态管理：Zustand store 按模块拆分（taskStore, userStore, uiStore）
  - API 设计：RESTful，路径前缀 /api/v1/
  - 样式方案：CSS Modules，每个组件对应一个 .module.css
- 关键文件：
  - .architecture.md：项目根目录
  - 入口文件：src/App.tsx
  - 配置文件：vite.config.ts, tsconfig.json

### 已知技术债
- [!!] 紧急：TaskCard 状态管理需重构，5种状态切换逻辑分散在3个组件中（tech_debt.md #3）
- [!] 高：缺少单元测试覆盖，TaskList 和 TaskDetail 无测试（tech_debt.md #5）
- [i] 中：部分组件 CSS 重复，可抽取公共样式变量

### 用户要改什么
用户想给 TaskCard 增加"优先级"标签功能（高/中/低三种颜色标签），并在 TaskList 中支持按优先级排序。

改动类型：UI + 逻辑

### 用户偏好
- 沟通风格：简洁直接，不啰嗦
- 技术偏好：React + TypeScript，偏好函数式组件
- 特殊要求：所有改动需要考虑移动端适配
```

---

## 使用说明

1. **Coach 填写时机**：入口判断确定需要移交时，立即填写移交摘要
2. **Receiver 接收时机**：收到移交摘要后，确认收到，然后开始 Step 1（理解现状）
3. **完整性检查**：填写后检查以下字段是否完整：
   - [ ] 项目概况（名称、状态、路径）
   - [ ] 已完成模块（至少列出3个）
   - [ ] 关键架构决策（技术栈、部署方式、重要约定）
   - [ ] 已知技术债（至少标注紧急和高优先级）
   - [ ] 用户要改什么（一句话概括）
   - [ ] 用户偏好（沟通风格、技术偏好）
4. **存储位置**：移交摘要应保存在 `data/projects/{project_name}/HANDOFF.md`，供 Receiver 和后续维护者查阅
