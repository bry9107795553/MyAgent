## 一、项目简介

**MyAgent** 是一个完全本地化、隐私优先的多角色 AI 智能体平台，全部推理在 AMD Radeon GPU 上通过 llama.cpp + ROCm 完成，**零云端依赖、可离线运行、用户数据不出本机**。

平台用 1 个"主控（Master）"角色作为防火墙与调度器，协调 18 个专业角色 + 1 个常驻"秘书"角色，覆盖软件开发全流程、知识工作、个人生产力等场景。任何复杂任务都被拆解成多角色流水线，逐步交付可验证的产物（代码、文档、报告），且每个角色拥有独立的存储与记忆，互不污染。

## 二、应用场景

| 场景 | 说明 |
|------|------|
| **软件开发全流程** | 从需求分析到部署，由 Coach→Designer→Developer→Inspector→Tester→Deployer 等角色协作完成（19 个角色覆盖全生命周期） |
| **知识工作** | 研究报告、文档写作、翻译、数据分析，多角色质量把关（Quality Checker 盲审） |
| **个人生产力** | 日程管理、创意头脑风暴、代码审查、文件整理 |
| **离线优先环境** | 无网络也能完整运行，适合隔离网络或弱网场景 |

**目标用户**：需要 GPU 加速 AI 辅助、又不愿把数据交给云端的开发者、研究员、写作者及隐私敏感个人。

## 三、Agent 架构

### 3.1 四层架构

```
+---------------------------------------------------+
|  L4  UI 层                                          |

|  对话视图 · 工作台视图 · 皮肤市场                      |
+---------------------------------------------------+
|  L3  智能体配置层（目录隔离）                          |
|  data/agents/{agent_id}/                           |
|  config.yaml → 主控人格 / 角色池 / 工具              |
|  prompt.txt  → 自定义系统提示                        |
|  knowledge/  → 知识库 · ui_layout.json             |
+---------------------------------------------------+
|  L2  编排层（常驻运行）                               |
|  FastAPI + WebSocket + 调度器 + 19 角色              |
|  + 四级渐进记忆 + 共享黑板                             |
|  主控分发 · 角色协作 · 智能体生成                      |
+---------------------------------------------------+
|  L1  基础层                                          |
|  llama.cpp + ROCm + Nginx                          |

+---------------------------------------------------+
```

### 3.2 19 角色系统

主控（Master）角色充当**防火墙与分发器**：所有请求先经 Master，角色之间不直接通信，只通过共享黑板（带访问控制的发布/订阅）交换信息。

- `data/role_pool.json` 中声明 **18 个**可分发角色；
- **秘书（Secretary）** 是常驻后台角色（实现于 `backend/core/agent/secretary.py`），观察每一轮对话而非被分发，负责任务记录与经验注入。

角色按能力分组（节选关键角色）：

| 分组 | 代表角色 | 能力 |
|------|----------|------|
| 通用 | Master / Writer / Translator / Scheduler / Creative / Quality Checker / Knowledge Retriever / Visual Analyzer | 分发防火墙 / 写作 / 翻译 / 日程 / 创意 / 质检 / 检索 / 多模态 |
| 开发 | Coach / Designer / Developer / Inspector / Tester / Deployer / Handoff Receiver | 需求编排 / 设计 / 编码 / 架构审查 / 测试 / 部署 / 存量项目接管 |
| 运维 | Cleaner | 文件系统清理 |
| 管理 | HR Manager / Experience Evaluator | 角色审计 / 经验评分与记忆裁剪 |
| 核心 | Secretary（常驻） | 轮次记录 / 经验注入 / 摘要 |

> 完整 19 角色及 GPU 亲和标签见 `README.md` 的「19-Role System」表。

### 3.3 预设工作组（Workgroup）

系统内置 10 条流水线，按触发词自动组装角色：

- `dev_full`：Coach → Designer → Coach → Developer → Inspector → Tester → Deployer → Cleaner
- `dev_modification`：Handoff Receiver → Inspector → Designer → Developer → …（存量项目改造）
- `report_writing`：Knowledge Retriever → Writer → Quality Checker → Writer
- `research_investigation` / `dev_code_review` / `dev_design_only` / `dev_tech_debt` / `translation_task` / `schedule_planning` / `visual_analysis_task`

开发类流水线在完成时自动追加 **Experience Evaluator** 步骤，对运行中注入的经验打分并裁剪陈旧记忆。

## 四、核心能力

1. **自然语言生成智能体**：用大白话描述需求，AI 自动生成完整智能体配置（人格、角色池、工具、知识库），零编码。
2. **四级渐进记忆（4-Level Progressive Memory）**
   - L0 原始归档：完整消息存档，仅追加，零丢失
   - L1 轻量摘要：每 5–10 轮增量摘要，用于上下文注入
   - L2 稠密摘要：跨会话语义压缩，长期记忆
   - L3 知识三元组：实体-关系抽取，结构化知识检索
   - 先写后压，保证不丢数据。
3. **动态调度系统**：关键词/语义匹配 + 动态工作组组装；单卡部署时角色在单一 llama-server 上顺序执行。
4. **项目状态追踪**：通过 `PROJECT_STATUS.md` 跨会话感知进度，重启后自动恢复上下文。
5. **目录级隔离**：智能体与角色均为独立文件夹，增删即增删文件夹，看门狗热重载，无需重启系统。
6. **秘书经验系统**：跨会话记录成功操作模式，同类任务自动注入相关经验，避免重复试错。
7. **工具调用（真实落盘）**：内置文件读/写/列、代码执行、网页搜索等工具——文件类工具直接操作磁盘，产物可验证、可追溯。

## 五、模型与本地部署方案

### 5.1 使用的模型

| 模型 | 规模 | 量化 | 默认单卡部署是否加载 | 用途 |
|------|------|------|:---:|------|
| Qwen3-30B-A3B MoE | 30B (3B active) | GGUF | **是**（支撑全部 19 角色） | 主推理、代码生成 |
| Qwen2.5-14B-Instruct | 14B | GGUF Q4_K_M | 备用（install.sh 默认下载） | 备选模型 |
| Qwen2.5-VL-7B-Instruct | 7B | GGUF | 否（仅多卡） | 多模态视觉分析 |

云实例使用 **Qwen3-30B-A3B MoE**（仅 3B 参数激活，推理速度 ~104 tok/s），本地部署默认用 Qwen2.5-14B。

参考部署（也是演示视频所展示的）在 **单张 Radeon PRO W7900（48GB，gfx1100，ROCm 7.2）** 云实例上，用单个 Qwen2.5-14B-Instruct Q4_K_M 实例支撑整个角色系统。

### 5.2 部署架构（默认单卡）

```
                +----------+
                |  Nginx   |  :80
                +----+-----+
                     |
        +------------+------------+
        |                         |
+-------v--------+     +---------v-------+
|  FastAPI:8080  |     |  Frontend Dist  |
+-------+--------+     +-----------------+
        |
        |  settings.resolve_inference_url()
        |  SINGLE_GPU_MODE=true → 全部 19 角色
        |
 +------v-------------------+
 |  llama-server  :8000     |
 |  Qwen3-30B-A3B MoE       |
 |  Radeon PRO W7900 / 48GB |
 +--------------------------+
```

- `SINGLE_GPU_MODE=true` 为默认值（`backend/config/settings.py`），启动即打印解析后的路由，一眼可验证。
- 一键部署：`bash install.sh`（安装依赖）→ `bash start.sh`（起全部服务）；也提供 `notebooks/setup_and_run.ipynb` 在 Radeon Cloud Jupyter 环境一键跑通。
- 多卡扩展（可选）：每个角色带 `gpu_affinity` 标签（gpu0/gpu1/gpu2），多卡主机上无需改代码即可并行调度。

### 5.3 100% 本地推理保证（可审计）

本项目**所有模型推理 100% 在本地 AMD Radeon GPU 完成，代码中不存在任何远程 API 路径**——不是被禁用，而是根本不存在。三处可审计：

| 审计点 | 文件 | 作用 |
|--------|------|------|
| 运行时硬 guard | `backend/config/settings.py` → `assert_local_endpoint()` | 任何非 localhost/127.0.0.1 的推理地址都会抛 `RemoteInferenceForbidden` 并拒绝启动 |
| 无客户端、无密钥 | `backend/core/llm/gateway.py` | 网关只有 local / none 两种模式，无 cloud 模式、无 API key 字段 |
| 配置面封闭 | `settings.py` → `Settings(extra="ignore")` | 未知环境变量（如 `OPENAI_API_KEY`）无字段可绑定，被静默丢弃，无法重新开启任何远程路径 |

（`openai` 依赖仅作为连接本地 llama-server 的 OpenAI 协议客户端库使用，请求从不离开本机。）

## 六、AMD Radeon GPU 推理速度优化说明

### 6.1 HIPBLAS 原生加速

项目使用 **llama.cpp 编译开启 `-DGGML_HIP=ON -DGGML_HIPBLAS=ON`** 获得原生 ROCm 加速，所有矩阵运算（注意力、FFN、embedding）经 HIPBLAS 卸载到 AMD GPU，在 Radeon 硬件上接近 CUDA 表现。

### 6.2 让 19 个角色挤进单张 48GB 卡

- **Q4_K_M 量化**：14B 权重仅占 ~9GB（FP16 约 28GB）
- **GQA 感知 KV 预算**：Qwen2.5-14B 仅 8 个 KV 头，KV 缓存约 0.1875 MiB/token，即便 32K 上下文总占用也低于 ~18GB
- **角色顺序执行**：角色轮流占用 GPU 而非竞争显存，峰值受单个活跃上下文约束
- **全量 offload（`-ngl 99`）**：每一层都在 Radeon GPU 上，无 CPU 回退路径

### 6.3 其他显存与速度优化

- GGUF Q4_K_M 量化：14B 模型显存从 ~28GB 降至 ~9GB，质量损失极小
- 上下文感知批大小：根据可用显存动态调整 `--ctx-size`
- 无 PyTorch 开销：llama.cpp 消除 Python/CUDA 运行时开销，减少显存碎片

### 6.4 A/B 测速开关（速度分支撑）

代码内置 `PROMPT_VARIANT` 开关：不设走原版 `prompt.txt`（A 组基线），设 `slim` 走 `prompt.slim.txt`（B 组精简版），切换只需环境变量，**无需改代码、无需重启模型服务**。

> **实测数据**：A/B 真实测速（TTFT、端到端耗时、prompt_tokens、质量盲评）将在云实例部署后按 `CLOUD_BENCHMARK.md` 脚本采集并填入本节。当前部署验证：已在单卡 Radeon PRO W7900（ROCm 7.2）实例完成全链路部署，19 角色经单一 llama-server 稳定运行，nginx 前端返回 HTTP 200。[实测数值待补]

## 七、隐私与数据安全

- **目录级角色存储隔离**：每个角色拥有独立工作记忆与会话记忆（落盘 `data/memory/sessions/{role}.json` + 崩溃缓存 `cache/{role}.json`），角色间不共享私有状态，杜绝上下文污染。
- **本地推理无远程 API**：所有推理在本地 GPU，数据不出机。
- **黑板防火墙脱敏**：角色间通过共享黑板交换信息，发布/订阅带访问控制，敏感字段脱敏。
