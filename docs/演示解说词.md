## S1 · 开场与本地推理证明（0:00 — 0:25）

【终端：rocminfo + rocm-smi 自证硬件，随后切分屏：左浏览器对话页，右终端 rocm-smi 实时监控】

MyAgent 是一套完全私有化部署的多角色 AI 团队。全部推理跑在这一张 AMD Radeon PRO W7900 上，48GB 显存，llama.cpp 加 ROCm 本地推理，不调用任何云端 API。

我输入"你好"。注意右边——GPU 利用率直接冲起来，显存占用十一到十三 GB。这是本机这张卡在算，不是在转发远程接口。

## S2 · 工具真实落盘（0:25 — 1:00）

【分屏：左浏览器对话页，右终端 cd 到项目目录】

先看清楚，这个目录现在是空的，文件不存在。

现在让它用 file_write 工具写一个待办清单文件……工具执行完，回到同一个终端——文件真的在磁盘上，内容就是它刚生成的，时间戳是刚才这一秒。

这不是模型编出来的一段文本，是真实的文件系统写入。

## S3 · 多轮对话记忆（1:00 — 1:40）

【浏览器全屏：对话页】

再看记忆。我先告诉它——我叫张三，技术栈是 Rust。再问一遍，它记得清清楚楚。

注意左边对话历史栏，这段对话已经自动保存了。现在点加号新建一个对话，问同样的问题——它说不知道。新的对话是全新的上下文，之前的记忆不会泄漏过来。

底层是四级渐进记忆：每轮对话独立归档，切换即隔离。

【分屏：左浏览器对话页，右侧 rocm-smi 监控。镜头对准右栏流水线面板】

流水线跑完后，切到预览 Tab，能看到生成的 HTML 页面。

## S6 · AMD 推理速度 A/B 测速（2:55 — 3:25）

【终端全屏：bench_report 输出对比结果】

速度优化这块我们做了严格 A/B 测试：同一台机器、同一个 Qwen2.5-14B 模型、同一个输入，唯一变量是角色 prompt 版本。用环境变量 PROMPT_VARIANT 秒切，不改一行代码。

原版基线对比精简版——prefill 词元从 XX 降到 YY，端到端耗时降低 ZZ%。这些是 llama-server 返回的真实 prompt_tokens，不是估算。

【左：项目架构图，右：终端 grep assert_local_endpoint】

一句话总结：19 个角色、四级记忆、真实工具落盘、可拖拽工作台，全部跑在一张 AMD Radeon PRO W7900 上。

## 实战提示

1. **语速**：每秒约 4-5 个汉字。全稿约 700 字，旁白约 2 分半，其余时间是画面操作和停顿。
2. **S6 占位符 XX / YY / ZZ**：云端 A/B 测速跑完后，用 bench_report 的中位数回填，**绝不编数字**。
3. **S6 降级方案**（实测数据未采集时）：只演示切换机制，旁白改为「实测 TTFT 与吞吐数据将随提交材料一并给出」。
4. **S4 流水线超时**：若超过 90 秒未跑完，保留首尾镜头，中段 4-8 倍速。
5. **遇到 LLM 回复不符预期**：不要慌，保持自然语气覆盖过去，录完再重录该镜头。
